.gitignore ジェネレーターの使い方

Node.js・Python・Java・Go・Rust・Ruby・PHP といった言語や、macOS・Windows・Linux などのOS、VSCode・JetBrains・Xcode などのエディタ、Unity・Laravel・Next.js といったフレームワークの .gitignore テンプレートを、チップをクリックして選ぶだけで一括生成できる無料ツールです。インストールや会員登録は不要で、すべての処理はお使いの端末内で完結します。

使い方はかんたんです。上部の一覧から使用しているスタックのチップをクリックして選択（複数選択可）すると、下のテキストエリアに .gitignore の内容が即座に生成されます。各スタックは「# === 名前 ===」という見出しごとにまとめられ、複数のスタックで重複するパターン行は自動的に取り除かれます。あとは「コピー」でクリップボードに取り込むか、「ダウンロード」で .gitignore ファイルとして保存してリポジトリのルートに配置するだけです。

こんな場面に

新しいリポジトリを作った直後の初期設定、複数言語を組み合わせたプロジェクトの無視ルールづくり、macOS の .DS_Store や Windows の Thumbs.db といったOS固有ファイルの除外、エディタの設定フォルダやビルド成果物の除外などにお使いいただけます。生成後はテキストエリア上でそのまま行の追記・削除ができるため、プロジェクト固有の生成物にも合わせられます。

.gitignore の基本

.gitignore は、Git にバージョン管理させたくないファイルやフォルダのパターンを1行ずつ記述する設定ファイルです。ビルド生成物、依存パッケージのディレクトリ、OSやエディタが自動生成する一時ファイル、API キーやパスワードを含む環境変数ファイルなどを除外することで、リポジトリを軽く・安全に・レビューしやすく保てます。通常はリポジトリのルートに置き、ルール全体がリポジトリ全域に適用されます。

記法意味例
名前 / パターン一致するファイル・フォルダを無視node_modules/、*.log
末尾スラッシュディレクトリのみを対象build/
先頭の !直前で無視した対象を除外（再包含）!important.log
先頭の #コメント行（無視ルールではない）# === Node ===

重複排除の仕組み

複数のスタックを選ぶと、たとえば「.DS_Store」や「*.log」のように複数のテンプレートに共通するパターン行が現れることがあります。本ツールは各見出しを保持したまま、すでに出力済みのパターン行を検出して二重に並ばないよう自動的に重複排除します。これにより見通しの良い、無駄のない .gitignore を得られます。なおコメント行や空行は見出しの区切りとして扱い、重複排除の対象にはしません。

よくある質問

.gitignore とは何ですか？
.gitignore は Git にバージョン管理させないファイルやフォルダのパターンを記述する設定ファイルです。ビルド成果物、依存パッケージ（node_modules など）、OSやエディタが生成する一時ファイル、秘密情報を含む .env などを除外することで、リポジトリを軽く安全に保てます。本ツールは主要スタックの推奨パターンをまとめて生成します。
複数のスタックを同時に選べますか？
はい。Node・Python・macOS・VSCode のように複数のチップを選ぶと、それぞれのテンプレートが「# === 名前 ===」の見出し付きで結合されます。同じパターン行は自動的に重複排除されるため、複数選択しても同一の無視ルールが二重に並ぶことはありません。
生成した内容はサーバーに送信されますか？
いいえ。すべてのテンプレートはページ内に埋め込まれており、結合・重複排除・コピー・ダウンロードのすべてがお使いのブラウザ内だけで完結します。外部APIへの通信は行わず、選択内容やファイル内容がサーバーへ送られることはありません。オフラインでも動作します。
.gitignore はどこに置けばよいですか？
通常はリポジトリのルートディレクトリに .gitignore という名前で置きます。ルートに置いたルールはリポジトリ全体に適用されます。サブディレクトリ固有の除外をしたい場合は、そのフォルダ内に個別の .gitignore を置くこともできます。既に追跡済みのファイルは .gitignore を追加しても除外されないため、その場合は git rm --cached で追跡を外してください。
生成されるパターンはそのまま使えますか？
はい、代表的で広く使われている無視ルールを収録しているため多くのプロジェクトでそのまま利用できます。ただしプロジェクト固有の生成物や独自のディレクトリ構成は網羅していないため、生成後に必要な行を追記・調整してご利用ください。編集はそのままテキストエリア上で行えます。
