選ぶだけで貼り付け可能なserverブロックを自動生成

基本設定

オプション

生成された nginx 設定

    


    
生成される設定はプレースホルダを含む雛形です。適用前に nginx -t で構文チェックを行い、証明書パスや root などを実環境に合わせて調整してください。すべての生成処理はお使いの端末内（ブラウザ）で完結し、サーバーへの送信は一切行いません。


    


    

        
nginx設定ジェネレーターの使い方

        
server_name・ドキュメントルート・ポート・SSLの有無・リバースプロキシのアップストリーム・gzip・HTTPからHTTPSへのリダイレクト・SPA向けのtry_filesをフォームで選ぶだけで、そのまま貼り付けて使えるnginxのserverブロックを自動生成する無料ツールです。設定ファイルの書式を覚えていなくても、代表的な構成をワンクリックで組み立てられます。インストールや会員登録は不要で、すべての処理はブラウザ内で完結します。

        
入力を変更するたびに下部の出力エリアがリアルタイムで更新されます。「コピー」ボタンで全文をクリップボードにコピーし、サーバー上の設定ファイルに貼り付けてください。証明書のパスやドキュメントルートはご自身の環境に合わせて置き換える前提の雛形です。

        
こんな用途に

        
静的サイトの公開、Node.jsやPython・PHPアプリのリバースプロキシ設定、React・VueなどのSPA配信、Let's Encryptを使ったHTTPS化と常時SSL化（HTTP→HTTPSリダイレクト）まで、よくある構成の初期設定をすばやく用意できます。学習用にディレクティブの書き方を確認する用途にも便利です。

適用の手順

        
生成した設定は、Debian／Ubuntu系なら /etc/nginx/sites-available/ に置き sites-enabled へシンボリックリンクを張る、CentOS系やその他の構成では /etc/nginx/conf.d/ に .conf ファイルとして配置します。保存後は必ず nginx -t で構文を確認し、成功したら systemctl reload nginx または nginx -s reload で反映してください。証明書のパスやドキュメントルートはプレースホルダなので、実環境の値に置き換えることを忘れないでください。


        
よくある質問

        
生成したnginx設定はどこに貼り付ければいい？
Debian／Ubuntu系では /etc/nginx/sites-available/ 内の設定ファイル、CentOSやその他の構成では /etc/nginx/conf.d/ 内の .conf ファイルに貼り付けます。編集後は nginx -t で構文チェックを行い、問題がなければ systemctl reload nginx または nginx -s reload で反映します。適用前に既存構成のバックアップを取ってください。

        
SSLを有効にすると証明書のパスはどうなる？
SSLを有効にすると listen 443 ssl; と ssl_certificate・ssl_certificate_key が出力されます。パスは /etc/letsencrypt/live/ドメイン/ 形式のプレースホルダで入るため、Let's Encrypt（certbot）ならそのまま、独自証明書なら実際のフルチェーン証明書と秘密鍵のパスに置き換えてください。

        
リバースプロキシとSPAのtry_filesは同時に使える？
このツールではロケーションの挙動を排他的に扱います。アップストリームを指定すると location / が proxy_pass を使い、指定しない場合はSPA向けの try_files または静的配信の try_files が出力されます。API はプロキシ、フロントは静的配信のような構成にしたい場合は、生成後に location ブロックを追加して調整してください。

        
HTTPからHTTPSへのリダイレクトはどう生成される？
SSLを有効にしたうえでリダイレクトを選ぶと、ポート80で待ち受ける専用のserverブロックが追加され、return 301 https://$host$request_uri; ですべてのアクセスをHTTPSへ転送します。メインのserverブロックは443番で待ち受けます。SSL無効時はリダイレクト先が存在しないため出力されません。

        
gzipを有効にすると何が追加される？
gzip on; と gzip_types（text/css・application/javascript・application/json・SVGなど）、gzip_min_length、gzip_vary on; などの圧縮ディレクティブが追加されます。テキスト系リソースを圧縮して転送量を削減します。すでに圧縮済みの画像や動画は対象から除外するのが一般的です。
